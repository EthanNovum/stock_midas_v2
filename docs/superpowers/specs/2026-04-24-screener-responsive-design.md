# Screener 页面响应式改造设计（方案 2）

## 1. 背景与目标

当前 `frontend/src/pages/Screener.tsx` 在大屏下受 `max-w-7xl` 限制，横向空间利用不足；在小屏下表格信息密集、阅读与操作体验较差。

本次改造目标：

1. 页面主内容改为全宽响应式容器，提升大屏可用宽度。
2. 筛选区改为紧凑布局，减少纵向占用，为结果区腾出空间。
3. 结果区改为双模式：手机卡片视图，平板/桌面表格视图。
4. 不修改业务逻辑，仅调整布局与展示层。

## 2. 范围与非目标

### 2.1 范围

- 文件：`frontend/src/pages/Screener.tsx`
- 内容：页面容器、筛选区排版、结果区响应式渲染结构、断点样式。

### 2.2 非目标

- 不改 API、数据结构、请求参数与后端接口。
- 不改筛选、排序、分页、导出逻辑。
- 不新增列配置功能（`Columns` 按钮保持现状）。

## 3. 方案选择

### 3.1 候选方案

- 方案 1：仅全宽 + 表格横滚（改动最小）
- 方案 2（采用）：全宽 + 紧凑筛选区 + 双模式结果区
- 方案 3：方案 2 + 折叠筛选区 + 吸顶操作栏（改动较大）

### 3.2 采用原因

方案 2 同时满足：

- 大屏宽度利用；
- 小屏可读性与可操作性；
- 开发复杂度可控，不引入额外交互负担。

## 4. 详细设计

### 4.1 页面主容器全宽化

位置：`Screener.tsx` 根容器（当前 `max-w-7xl mx-auto`）

改造要点：

- 去除最大宽度限制，改为 `w-full`。
- 使用断点内边距控制阅读宽度与边距：`px-3 sm:px-4 lg:px-6 xl:px-8`。
- 页面纵向间距使用断点化：`space-y-4 md:space-y-6 lg:space-y-8`。

预期效果：

- 1440/1920 等大屏不再“中间窄列”；
- 小屏仍保留合理留白。

### 4.2 筛选区紧凑化

位置：筛选区外层网格与两张筛选卡片。

改造要点：

1. 外层网格间距断点化：`gap-3 md:gap-4 lg:gap-5`。
2. 卡片内边距收敛：`p-4 md:p-5 lg:p-6`（替代固定 `p-8`）。
3. 数值筛选内部网格改为：`grid-cols-1 sm:grid-cols-2 xl:grid-cols-3`，并降低项间距。
4. 筛选项内部垂直节奏由 `space-y-3` 收敛为 `space-y-2`。
5. 属性 chip 调整为更紧凑的断点 padding（小屏更密集，大屏适度回升）。

预期效果：

- 中大屏首屏展示更多内容；
- 筛选区操作密度更高但不牺牲可点击性。

### 4.3 结果区双模式渲染

位置：结果区（标题栏 + 数据展示区 + 底部加载更多区）。

改造要点：

1. **桌面/平板模式（`md` 及以上）**
   - 保留当前表格结构与排序交互。
   - 容器使用 `hidden md:block`。
   - 保留 `overflow-x-auto`，并通过断点化单元格间距减少横向压力。

2. **手机模式（`md` 以下）**
   - 新增卡片列表容器：`md:hidden`。
   - 每个 `stock` 以卡片展示核心字段：
     - 名称/代码/行业
     - 最新价、涨跌幅、信号
     - 市值、PE、股息率
     - MA120、MA120×0.88、MA120×1.12
   - 保留现有信号样式语义（买入/卖出/观望）并映射至卡片。

3. 统一状态
   - 加载态、错误态、空态沿用同一数据与判断条件。
   - `sortedResults` 作为两套视图共同数据源，避免状态分叉。

预期效果：

- 手机端无需横向拖拽即可阅读核心信息；
- 桌面端维持高密度表格与排序体验。

## 5. 数据流与状态一致性

本次仅涉及渲染层，不改数据流：

- `fetchScreenerResults`、`sortConfig`、`sortedResults`、`handleLoadMore` 保持原逻辑。
- 双视图只共享读取同一状态，不新增业务状态。

## 6. 错误处理与可访问性

- 保持原错误信息展示路径（`errorMessage`）。
- 表格 `aria-sort` 继续保留。
- 卡片模式下保持按钮可触达、文字对比度与最小触控尺寸。

## 7. 验收标准

1. 1920 宽屏：页面可用宽度明显增加，筛选区与结果区显示更舒展。
2. 1280~768：筛选区紧凑但不拥挤，标题与按钮布局稳定。
3. <768：自动切换卡片模式，主要字段完整可读。
4. 加载中、错误、空结果、加载更多四类状态在两种模式均表现正确。
5. 排序、筛选、导出行为与改造前一致。

## 8. 实施清单（供后续计划拆分）

1. 调整根容器与主要区块的响应式 spacing/padding。
2. 重排筛选区网格与筛选项密度。
3. 将结果渲染拆分为 `DesktopTable` 与 `MobileCards`（可为组件或局部函数）。
4. 对表格单元格间距与 `min-w` 做断点化优化。
5. 手工验证三类断点（手机/平板/大屏）和四类状态（加载/错误/空态/正常）。
